# Finlite UI 设计规范

> 单一事实源。机器可读 token 见同目录 [`tokens.css`](./tokens.css)。
> OpenDesign 生成时：绑定 design system `ant`，先读本文件 + `tokens.css`，并参照基准页 `import-center.html`。

## 1. 视觉主题与基调

- **风格家族**：企业级、数据密集的桌面财务工具（Ant Design 取向）。
- **气质**：克制、专业、高信息密度；无营销装饰、无大圆角拟物、无花哨渐变。
- **桌面优先**：固定侧栏 + 顶栏 + 内容区，表格 sticky 表头。
- **中文界面**：所有文案、按钮、错误均为简体中文，且可执行。

## 2. 颜色

| 用途 | Token | 值 |
|---|---|---|
| 页面底 | `--surface` | `#f7f8fa` |
| 卡片/侧栏/表头 | `--bg` | `#ffffff` |
| 主文字 | `--fg` | `#111111` |
| 次文字 | `--fg-2` | `#374151` |
| 弱文字 | `--muted` | `#6b7280` |
| 边框 / 分隔线 | `--border` / `--border-soft` | `#d9dee7` / `#eceff4` |
| 主色 | `--accent` | `#1677ff` |
| 主色浅底 | `--accent-soft` | `#eaf2ff` |

- 主色只用于：主按钮、当前导航、链接、选中态、POS 等关键标签。
- **状态色必须用 oklch**，不得写死 hex：
  - 成功 `--ok: oklch(0.62 0.17 145)`（底 `--ok-bg` / 边 `--ok-border` / 字 `--ok-fg`）
  - 警告 `--warn: oklch(0.72 0.14 75)`
  - 错误 `--err: oklch(0.58 0.20 25)`
- 语义色只表达状态，不挪作他用。

## 3. 字体与数字

- 正文：`Inter` + 中文字体回退（`--font`）；等宽：`--mono`。
- 字号阶梯：`12 / 12.5 / 13 / 14 / 16 / 23 / 26`（表头 12、表格正文 13、正文 14、页标题 16、统计数值 23）。
- **金额/数量一律右对齐 + `font-variant-numeric: tabular-nums`**，统一两位小数、千分位（如 `11,970.00`）。
- 日期：业务日期 `YYYY-MM-DD`；时间戳 `RFC3339`。

## 4. 间距、圆角与阴影

- 间距走 8pt 网格：`4 / 8 / 12 / 16 / 20 / 24`。
- 圆角：`4`（chip/tag）、`6`（按钮/输入）、`8`（卡片/表格容器）、`12`（弹窗/抽屉）。
- 阴影克制：卡片仅 `--shadow-sm`；弹窗/抽屉用 `--shadow-lg`。
- 布局尺寸：侧栏 `220px`、顶栏 `52px`。

## 5. 组件规范

- **按钮**：默认白底描边；主操作 `--accent` 蓝底白字；撤销/危险操作红色描边；状态变更类操作必须二次确认弹窗。
- **表格**：sticky 表头（`--surface` 底）、行 hover 变浅、末行去边框；数字列右对齐等宽；状态列用圆角 badge。
- **徽标/标签**：胶囊形 `--r-pill`；类型标签（银行流水/订单流水/POS 清算）用浅底 + 小圆点。
- **表单**：高度 28–32px，聚焦态 `--focus-ring`；金额输入用等宽数字。
- **抽屉 / 弹窗**：右侧抽屉放详情与审核；居中弹窗放列映射预览与确认；遮罩 `rgba(17,24,39,.32)`。
- **提示条 / Banner**：info / ok / warn / danger 四语气，分别用主色浅底与三色状态底。
- **Stepper**：用于多步流程（导入中心）。

## 6. 状态色映射（跨模块统一）

| 模块 | 状态 | 呈现 |
|---|---|---|
| 银行余额校验 | `ok` 正常 | 绿 badge / 淡绿左边框 |
| | `mismatch` 不平 | **整行淡红底 + 红左边框 + 红 badge** |
| | `skip` 跳过 | 灰 badge |
| | `confirmed` 已确认 | 绿 badge「已确认」 |
| 订单费率检查 | `fee_diff` 费率差异 | 黄 badge + 淡黄整行 |
| | `net_diff` 实收差异 | 红 badge + 淡红整行 |
| | `fee_parse_err` 解析失败 | 红 badge |
| 汇总 | `draft/reviewed/vouchered` | 灰 / 绿 / 蓝 |
| 凭证 | `draft/audited` | 灰 / 绿 |
| 店面收款 | `draft/confirmed/summarized/voided` | 灰 / 绿 / 蓝 / 灰+删除线 |

## 7. 硬性业务约束（设计层必须体现）

- 原始表（银行流水/订单流水）**只读**，页面无编辑/删除入口。
- 破坏性或状态变更操作（确认余额、审核、反审核、作废、恢复备份）**必须二次确认**。
- **明细/批次列表一次性完整展示，禁止分页**（长列表用内部滚动 + sticky 表头）。
- 金额全链路 `decimal`，前端仅格式化；错误信息中文可执行（如「借贷不平：借 12,000.00 ≠ 贷 11,970.00」）。
- 脱敏：示例数据不得出现真实公司/人名/完整账号（账号形如 `1001****7575`）。

## 8. 如何在 OpenDesign 后续生成中强制沿用

1. **绑定 design system**：`create_project({ designSystem: "ant", skill: "design-md" })`，或 `start_run({ plugin: "design-system-ant" })`。
   design system 内容来自 `od://design-systems/ant/DESIGN.md`。
2. **把本规范写进项目**：生成前将 `DESIGN.md` 与 `tokens.css` 写入项目根，并放一份基准页（如 `import-center.html`）。
3. **Prompt 固定前导**：
   > 严格遵循项目根 `DESIGN.md` 与 `tokens.css`（色板/字体/间距/圆角/状态色），参照 `import-center.html` 的组件形态；**不得自创配色/字体/圆角**；明细列表一次性完整展示、禁止分页；中文界面、金额等宽右对齐、示例脱敏。
4. **同项目追加迭代**以延续上下文（注意会话恢复偶发卡死，必要时新建项目）。
