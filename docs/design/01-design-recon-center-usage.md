## 1. 模块定位

对账中心处于 MVP 主流程第 3 步：

```
导入中心 → 银行流水 / 订单流水 → [对账中心] → 数据汇总 → 凭证管理 → 科目余额表
                                      ▲
                              按结算日三方勾稽
```

**核心目标**：把"订单实收、银行 POS 转入、汇总实际收入"三条口径按**结算日期**对齐，输出两种日期：

- **三方一致** → 可进入数据汇总页生成草稿；
- **差异待处理** → 进待处理队列，**永不阻塞**其他日期的制单。

**明确不做**：不修改原始表（`bank_flows` / `order_flows` 只读）；不直接生成凭证（凭证只能由"已审核汇总"生成）；不做跨期自动核销。

## 2. 使用前置条件

| 前置 | 说明 |
|---|---|
| 已导入银行流水 | 导入中心（F1）完成，余额批次状态已知（§6.3） |
| 已导入订单流水 | 导入中心（F1）完成，手续费复算差异已了解（F3） |
| 已录入数据汇总 | 未录则"汇总实际收入"列对不上，属**正常现象**，先补录再回来对账 |
| 已知会计期间 | 默认当前月，可切换月份或用区间筛选 |

> 只导入了银行和订单、还没录汇总时：可先用"订单实收 vs 银行 POS"两栏判断清算是否到账；"汇总实际收入"列为 0 时不视为错误，待汇总补录后重新对账即可。

## 3. 界面结构（目标态）

参照 `docs/uidesign/reconciliation.html`，页面自上而下分为四块：

### 3.1 顶部操作栏

- **会计期间**：显示当前账期（如 2026 年 7 月）；
- **导出对账单**：导出当前筛选结果为 TSV/CSV，供归档或发给审核人；
- **重新对账**：按当前期间/区间重算，刷新列表与统计卡。

### 3.2 统计卡（四张）

| 卡片 | 口径 | 用途 |
|---|---|---|
| 对账总金额（POS 实收） | 区间内银行 POS 转入合计 | 一眼看清算总额 |
| 已匹配 | `已核对结算日 / 区间结算日` | 进度感知 |
| 差异待处理 | 差异笔数 + 差异金额 | 待办入口 |
| 待汇总生成 | 已匹配但尚无汇总草稿的天数 | 推动下一步制单 |

### 3.3 筛选与主表

- **Tab 筛选**：全部 / 已匹配 / 差异（带计数）；
- **期间/日期搜索**：按会计期间或日期、金额搜索；
- **主表列**：展开箭头、结算日期（含星期）、订单实收合计、银行 POS 转入、汇总实际收入、差异、状态、操作；
- **状态色**：三方一致=绿、差异待处理=黄（同业务文档 §6.3 的红/绿/灰体系，此处以"黄"表"待处理"而非"银行余额不平"）；
- **底部合计**：已匹配合计、差异合计、结算日数、数据截止时间。

### 3.4 行展开下钻（差异定位的关键）

点击任意结算日行，展开**三栏对照**，每栏带小计，便于逐笔定位：

```
┌─ 订单流水 (n 笔) ──┬─ 银行流水 (POS 转入) ─┬─ 数据汇总 (n 行) ──┐
│ 客户 / 支付 / 金额 │ 时间 / 对方 / 附言    │ 收据号 / 事由 / 实际 │
│ 手续费             │ 转入                  │                      │
├ 实收合计 ──────────┼ 转入合计 ────────────┼ 收入合计 ──────────┤
└────────────────────┴──────────────────────┴──────────────────────┘
```

- 一致行操作按钮：**生成汇总**（跳数据汇总页，预填草稿）；
- 差异行操作按钮：**定位原行**（展开三栏）+ 差异分析说明 + **补录调整** / **忽略差异**。

## 4. 标准操作流程（SOP）

### 场景 A：日常对账（推荐每天一次）

1. 进入对账中心，确认**会计期间**正确；
2. 点 **重新对账**，读取当前区间全部结算日；
3. 看统计卡：若"差异待处理 = 0"，直接进入第 6 步；
4. 切到 **差异** Tab，逐条处理（见 §6）；
5. 处理完点 **重新对账** 复验，直至差异清零或均为已核实的可忽略项；
6. 对"三方一致"的日期点 **生成汇总**，进入数据汇总页补事由/备注/收据号；
7. 需要留痕时点 **导出对账单**。

### 场景 B：定位某天差异

1. 在 **差异** Tab 点击该日期行展开三栏；
2. 读差异分析文案，判断属于哪类（见 §6 表）：
   - "订单实收 vs 银行 POS" → 查订单流水补贴/立减、银行 POS 到账笔数；
   - "银行 POS vs 汇总实际收入" → 查数据汇总页当日收入行；
3. 点 **定位原行** 跳转对应列表页核对（文件 + 行号可追溯，§10）；
4. 处理方式：
   - 汇总漏录/错录 → 去数据汇总页**补录/修改**后回来复验；
   - 差异已核实且无需调账（如补贴/立减 0.45 元）→ 点 **忽略差异**（需二次确认，写审计日志）；
5. 回到对账中心点 **重新对账**。

### 场景 C：跨期/跨月复核

1. 切换会计期间到目标月份；
2. **重新对账**；
3. 关注"银行侧独有日期"（订单已导完但银行多出一笔 POS 入账，或反之）——这类日期同样会进待处理队列，不会被静默吞掉（§6.4、`ListDiffs` 实现说明）。

## 5. 状态与颜色约定

| 状态 | 颜色 | 含义 | 可用动作 |
|---|---|---|---|
| 三方一致 | 绿 | 订单实收 = 银行 POS 转入 = 汇总实际收入 | 生成汇总、导出 |
| 差异待处理 | 黄 | 三方至少两者不等 | 定位原行、补录调整、忽略差异 |
| 待汇总生成 | 灰 | 已匹配但尚未生成汇总草稿 | 生成汇总 |
| 无数据 | 灰 | 该结算日仅单侧有数据 | 定位原行 |

## 6. 差异处理规则

### 6.1 勾稽口径（业务文档 §6.4）

- 日粒度（结算日 = D）：
  `Σ订单(结算日期=D).net == 银行(D 入账).POS转入 == Σ汇总(D).实际收入`；
- T+1 归属：收入归属日取订单 `结算日期`，**不是**交易时间（§6.1）；
- 银行侧归集：`txn_time` 日期落在 D，且为 POS 行（附言为示例商户号或对方含"POS净收"）。

### 6.2 差异分类与处置

| 差异字段 | 典型原因 | 处置 |
|---|---|---|
| 订单实收 vs 银行 POS | 商户补贴/消费立减/银行补贴未入账（样本 7-01 差 0.45 元） | 核对订单 `raw_json` 补贴字段后**忽略差异**或按实调整 |
| 银行 POS vs 汇总实际收入 | 汇总漏录、金额录错、归属日期录错 | 数据汇总页**补录/修改**后重新对账 |
| 银行侧独有日期 | 清算笔数异常/跨期到账 | **定位原行**核对银行流水与订单缺口 |
| 订单侧独有日期 | 订单尚未清算入账 | 等次日银行入账后重新对账，暂不处理 |

### 6.3 硬性约束

- 差异**只进待处理队列**，不阻止任何其他日期生成汇总/凭证；
- **忽略差异**必须二次确认，并写入 `audit_logs`（old/new JSON、操作人），可追溯；
- 对账结果**不落库为结论**（按需实时重算），避免与原始表口径漂移；
- 原始表只读，任何"修改"都通过数据汇总补录或调整行实现，绝不 UPDATE `bank_flows` / `order_flows`。

## 7. 角色权限

| 角色 | 允许动作 |
|---|---|
| 出纳/会计（制单人） | 查看对账、展开下钻、生成汇总草稿、导出对账单 |
| 审核人 | 出纳权限 + **忽略差异**、复核确认 |
| 管理员 | 全部 |

首版单机单用户，不做并发控制，但"忽略差异"等状态变更动作预留 `operator` 字段。

## 8. 与相邻模块的关系

| 相邻模块 | 交互 |
|---|---|
| 导入中心（F1） | 对账的数据来源；导入批次与余额警告影响对账可信度 |
| 银行流水（F2）/ 订单流水（F3） | "定位原行"落点，展示文件 + 行号 + `raw_json` |
| 数据汇总（F5） | "生成汇总"落点；仅"三方一致"的日期可预填草稿 |
| 凭证管理（F6） | 对账不直接生成凭证；只能由"已审核汇总"生成 |
| 科目余额表（F7） | 间接：对账 → 汇总 → 凭证 → 余额表 |

## 9. 现状与差距

当前实现（`internal/services/recon_service.go` + `frontend/src/routes/Recon.svelte`）：

- ✅ `ReconcileByDate(date)`：单日三方勾稽，返回订单实收/银行 POS/汇总实际/差异/是否匹配；
- ✅ `ListDiffs(dateFrom, dateTo)`：区间待处理队列，日期取"订单结算日 ∪ 银行 POS 入账日"，按差异字段分类；
- ✅ 前端：单日对账 + 差异表 + "定位该日"。

与目标态的差距（待实施）：

| 缺口 | 说明 |
|---|---|
| 区间对账结果表 | 现仅单日查询；目标需一次列出区间内全部结算日及其状态 |
| 统计卡 / Tab 筛选 | 未实现 |
| 行展开三栏下钻 | 未实现（需按日拉取订单/银行/汇总明细） |
| 生成汇总跳转 | 未实现（需复用 `SummaryService` 预填） |
| 忽略差异 / 补录调整 | 未实现（需新增动作 + `audit_logs`） |
| 导出对账单 | 未实现 |
| 期间切换 | 现为裸日期选择，无会计期间概念 |

## 10. 分期实施建议

### P0 — 区间对账与列表（对齐"能看全"）

- 新增 `ReconService.ReconcileRange(ctx, dateFrom, dateTo) ([]ReconResult, error)`（复用现有逐日逻辑）；
- 前端改为：期间/区间选择 → 一次渲染全部结算日，状态色 + 差异合计；
- 统计卡（总额/已匹配/差异/待汇总）在前端由 `ReconcileRange` 结果派生，无需新后端接口。

### P1 — 下钻与联动（对齐"能定位"）

- 新增 `ReconService.ListDayDetail(ctx, date) (ReconDayDetail, error)`：返回该结算日的订单行、银行 POS 行、汇总收入行（含文件+行号、`raw_json` 摘要）；
- 前端行展开三栏对照；
- "生成汇总"跳转数据汇总页并带日期，调用既有预填逻辑。

### P2 — 差异动作与导出（对齐"能闭环"）

- `ReconService.IgnoreDiff(ctx, date, field, remark)`：写 `audit_logs`，标记忽略（建议新增轻量表 `recon_ignores(date, field, remark, operator, created_at)`）；
- "补录调整"跳数据汇总页新增行；
- 导出对账单（TSV/CSV，复用导入侧格式约定）。

> 所有新增方法遵循项目约定：`context.Context` 首参、返回 `(T, error)`、金额用 `decimal`、错误中文可执行。新增/变更表结构走 `db-schema` 技能与 `internal/store/upgrade/` 增量脚本。

## 12. 字段口径速查

| 列 | 来源表 | 字段 | 口径 |
|---|---|---|---|
| 订单实收合计 | `order_flows` | `SUM(net_amount)` | `settle_date = D` |
| 银行 POS 转入 | `bank_flows` | `SUM(in_amount)` | `substr(txn_time,1,10)=D` 且 POS 行 |
| 汇总实际收入 | `data_summaries` | `SUM(income_amount)` | `date=D` 且 `category='收入'` |
| 差异 | 派生 | `orderNet - bankPOS` | `shopspring/decimal` 严格相等 |
| 结算日集合 | 派生 | — | 订单 `settle_date` ∪ 银行 POS `txn_time` 日期 |
